### 已定结论

1. **连续天数改成批量算**：`repo.Report.Streaks(ctx, familyID, today)` 一条 SQL 取全组
   400 天内的 `screen_reports`，按 `member_id` 分组在内存里回溯；`CurrentStreak` 已删除
   （唯一调用点就是榜单，不留兼容分支）。口径不变：最近一条必须是今天或昨天且达标。
2. **加索引 `idx_family_date (family_id, report_date)`**：原表只有 `uk_member_date`，
   全组扫描会走全表。按开发阶段铁律直接改 `0001_init`（未新增迁移文件）。
3. **实测提升约 2.7 倍**：4 人家庭 2.06/3.22/4.67s → 1.22/1.22/1.63/1.05/1.60s。
   剩余 ~1.2s 是**远端 MySQL 两次往返 RTT**（榜单 + 连续天数各一条 SQL），
   不是算法问题；要再压只能加缓存或把库搬到应用同机。
4. **脚本管理员登录统一**：新增 `scripts/lib_admin.sh` 的 `admin_login()`，
   优先 `ADMIN_PASSWORD` 环境变量，兜底 `admins1234 / admins123 / admins`。
