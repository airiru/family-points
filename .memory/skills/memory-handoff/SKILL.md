# 记忆交接协议

让工作记忆能被任何 AI 工具读懂，从而使工作在工具之间无缝接续，用户无需重复交代背景。

## 核心思路

skill 无法把文件"暴露"给其他工具。skill 只是一份指令，装在某个工具里就只对那个工具有效。
因此跨工具续接只有两个必要条件：

1. **路径固定** —— 所有工具读同一批记忆文件，路径永不改动。
2. **格式固定** —— 文件结构统一，任何模型解析结果都一致。

本 skill 同时提供这两者。任何装入了这份指令的工具，都能读到同一份记忆并接着干。

## 记忆文件位置

分两层，都在本协议读取范围内：

| 层级 | 路径 | 存放内容 |
|---|---|---|
| 用户级 | `<项目根>/.memory/user/MEMORY.md` | 通用约定、用户偏好、长期规则 |
| 项目级 | `<项目根>/.memory/MEMORY.md` | 项目约定、架构决策、长期有效的事实 |
| 项目日志 | `<项目根>/.memory/YYYY-MM-DD.md` | 当天所做工作的追加式记录 |

## 读取协议

开始任务时，或用户要求接着之前的工作继续时：

1. **先读项目级 MEMORY.md** —— 它经过提炼、篇幅短，存放能跨天存续的事实。文件不存在则跳过。
2. **再读用户级 MEMORY.md** —— 当任务不限于某项目，或项目记录中引用了跨项目规则时。文件不存在则跳过。
3. **读最近的日志，从新到旧**。至少往前读 2–3 天，不要只读当天。记忆是间歇性写入的——上周得出的结论可能仍是当前状态。读到足以理解当前进展即可停止。
4. **不要假设文件一定存在**。记忆文件缺失意味着"没有历史记录"，不是错误。用其他可得的上下文继续推进任务。
5. **把记忆当作线索，而非事实**。它记录的是上一个会话当时的认知。在依据其中关于代码或交付物的说法行事之前，先核对磁盘上的实际文件。记忆可能已经过时。
6. **先确认记忆根没有分叉**。工具自带的默认记忆目录（如 `<项目根>/.workbuddy/memory/`）可能与
   `.memory/` 并存，且会在启动时被提示给 agent。**以项目 `MEMORY.md` 里记录的路径为准**；
   另一处若为空、或只有一份重定向用的 `README.md` 存根，就是遗留目录 —— 不要往那里写。

## 用户只说「继续」时

这类指令没说做什么，**别只做一通总结就停**。按固定流程选活：

1. **读完记忆先汇总候选** —— 把最近几篇日志的「待办」，连同被标为「未修 / 未验证 / 待定 / 潜伏」的条目一起列出来。
2. **逐条核对磁盘**（读取协议第 5 条）。日志里的判断可能已经过时：代码可能已经改了、
   文件可能本来就在、用户可能已经改过主意。**核对常有意外收获** —— 被记成「只影响某个功能」的缺口，
   实际往往还牵连别的入口，危害被低估。
3. **挑一个可交付、可验证的动手**，优先不依赖长耗时构建或人工外观确认的。
4. **先给一段状态摘要再动手**：当前进度 / 已定结论 / 待办 / 你打算做哪一项及理由。
   用户可能只是想确认你已经接上了上下文。
5. **需要用户拍板的项（去留、改名、清理、方案取舍）单列出来问，不要替他决定**；
   若候选里只有这类项，就直接问。

## 写入协议

完成实质性工作后，追加到项目日志。当天文件不存在则创建。

如果某个事实是**应当跨天存续的约定或决策**（例如选定的框架、命名规则、架构约束），
则改写入 `<项目根>/.memory/MEMORY.md`，保持简洁并就地修改。

不要记录临时信息：搜索结果、临时路径、工具报错、未成形的想法。
判断标准是：未来的会话是否会因为这条信息而避免重做工作或违反约定。

### ★ 派发出去的工作，产物必须落盘（2026-09-18 实证）

把工作派给子任务 / 并行代理时，**必须在指令里要求它把结果写进文件**，不能只要求"回复我"。

真实案例：一次「功能调研」把第 2 路派发出去，工作区文件里记成「**已派发，结果未回**」；
下一个会话核对磁盘时发现**它根本没落过盘**（`.audit/` 全目录搜该路的关键词**零命中**）——
子任务的结果只活在当时的对话上下文里，**会话一结束就蒸发了**，「未回」其实是「已丢」。

配套判据（并入上面的「把记忆当线索」）：

- **读到记忆里写「已派发 / 进行中 / 结果未回 / 待补」时，先搜磁盘确认产物是否真的存在**，
  不要当「在途」继续等 —— 等一个已经不存在的东西，等于空转一个会话。
- 反过来，**派发时就把「写哪个文件」写进指令**。落盘的分工也定清楚：
  **合成层进交付物**（可 review），**证据层（原始矩阵、来源 URL）留 `<项目根>/.audit/`**。

### ★ 阶段完成即提交（强制）

**「一个阶段完成」的判据**：一组相关工作做完 **且验证过**（跑过构建 / 测试 / 桩测试，
或至少做了当前环境能做的静态检查）**且记忆已写**。三条都满足就**立即提交，
不要攒到会话结束** —— 攒着会跨工具、跨会话丢上下文，下一个会话也定位不到
「上一阶段到底改了什么」。

⚠️ **它不是「提交完接着做下一项」** —— 提交完 = **本阶段结束，停下来汇报**，
**下一项等用户指定**。判据：**用户指令一定有具体对象**（做哪一项、改成什么样）；
**无宾语的「继续 / continue / 接着做」是续跑提示，不是指令** → 停下来问，或只做只读 / 验证类工作。
（真实案例：用户只发「继续 / 接着做」，被当成连轴转的信号一路做了 6 个阶段才停 →
用户批评；判据与整改见该项目 2026-09-18 日志。）

**动作顺序**（缺一不可）：

1. **先写记忆**（见上），再提交 —— 两者属于同一个阶段。
2. `git status --short` 看**全部**变更，不是只看自己点名的那些。
   ⚠️ 批量操作（移动 / 删除 / 重命名）**前后都要对账**（`find | wc -l` 或文件清单对比）：
   真实案例里一整棵子树（139 个文件）在两条命令之间从**工作区**消失，而 git 索引里
   只有主动删的那 2 条 —— 属环境层抖动，**只有对账才会立刻发现**。
   ⛔ **但对账「个数」远远不够 —— 删文件前必须先做「内容级」核对**：
   逐节确认该文件的**每一部分都有别的载体**，再用 `diff` 证明迁移是**逐字节一致**的。
   真实案例（2026-09-18）：收尾时删掉一个「工作区文件」，只对账了文件个数
   （142 → 141，确实只少它一个）就交差 —— 而那个文件是**某一整路调研结果的唯一副本**
   （那一路没有独立产物文件），合成章节只搬了它 10 列里的 2 列 →
   **全矩阵与价格表被误删**，最后靠 git 才捞回来。
   **判据：「合成层已覆盖」只对「被真正搬过去的部分」成立**，不能拿一句「已被取代」整包处理。
   **结构上还要避免**：不要让任何一路的产物**只存在于工作区文件里** —— 每路都要有自己的产物文件，
   否则收尾清理时必然误删。
3. **只 `git add` 本阶段涉及的路径**。要用 `git add -A` 就先把 `git status --short`
   逐行看过，确认里面没有不属于本阶段的东西（临时产物、别处的改动）。
4. 提交信息**按仓库既有风格**（先 `git log -5 --format=%B` 看一眼），
   摘要一句话说清**为什么**；正文写：改了什么 / 验证证据 / **未验证的部分如实标注** /
   后续动作（含提交号，便于交接定位）。
5. **提交后再跑一次 `git status --short`** 确认干净（或只剩本就不该提交的文件）。

**不要做的事**：不要 `--amend`；不要跳过 hook（`--no-verify`）；不要改 git 配置；
不要提交疑似含密钥的文件（`.env`、凭证、私钥）。**用户没要求时不要 push。**

**例外**：纯读取 / 调研 / 问答类工作没有文件变更，自然无需提交 ——
**不要为了「有提交」而制造改动**。

## 日志格式要求

把记录结构化，使任何模型都能解析。使用以下固定标题：

```markdown
# 2026-09-15

## 当前进度
工作当前处于什么状态，一两句话说明。

## 已定结论
已经做出的决策和得出的结论，附上足够理由，避免日后重新争论。

## 待办
还没做完的事，明确、可执行。

## 关键路径
涉及的重要文件绝对路径：代码、交付物、配置。

## 约定
本次工作中发现的约定、约束或偏好。
```

某一节确实为空时才可省略。每条记录保持简短——这个文件会在未来会话开始时被读取，不应浪费上下文。

### 写入规则

1. **写入工作区以外前先确认**，包括工具配置目录、主目录、全局指令文件。
2. **目标文件已有内容时必须追加，绝不覆盖**。
3. 多数工具需要**重启或新建会话**才会加载新指令。
4. **本文件若同时存在于项目根与技能目录，改完必须同步** —— 两份副本会漂移，
   而且**漂移是静默的**（已实际发生两次：一次是整节「续写与体量控制（实践补充）」缺失，
   112 行 vs 132 行；更早一次连行尾都不一致）。按下面四步做：

   - **先找出技能目录的实际路径** —— 它**因工具而异**，而且**同一个工具可能有多个 home 目录**：
     WorkBuddy 实测**同时存在** `~/.workbuddy-ai/skills/<skill-name>/SKILL.md`
     （v5.5.2，当前会话实际加载的就是这里）和 `~/.workbuddy/skills/<skill-name>/SKILL.md`
     （v5.5.6）；其它工具可能用 `~/.zcode/skills/`、`~/.trae-cn/skills/`、`~/.claude/skills/`、
     `~/.codex/skills/` 等。拿不准就 `ls ~/.*/skills/` 看一眼，**不要凭记忆填路径**。
     ⚠️ **还有一类位置不在 `~/.*/skills/` 之下，`ls` 那一条会漏掉** —— 工具把自己的
     项目级/用户级配置根放在别处，技能挂在 `<配置根>/skills/` 下。已知实例（**DSH**，
     2026-10-12 实测）：项目级 `<项目根>/.dsh/skills/`、用户级 `~/.dsh/skills/`
     （另有两个候选根 `<项目根>/.agents/skills/`、`~/.agents/skills/` 当前为空）。
     ⇒ 发现副本时**除了 `ls ~/.*/skills/`，还要单独看这些「配置根」目录**；
     新增工具后先查它的配置根约定，别默认它也在 home 点目录的 `skills` 下。
     ⚠️ 不要预设"只有某一个会生效" —— 哪一个被加载取决于当前启动的版本。
     **凡是已经存在同名副本的位置，全部同步**，并各自核验 `diff` 为空。
     ⚠️ **别把位置写死成固定列表 —— 而且这个列表本身会变**（同一条教训一天内命中两次）：
     · **2026-09-23** 实测 4 份：项目根 + `~/.workbuddy-ai/` + `~/.workbuddy/` + **`~/.trae-cn/`**。
       而本文档原先只列了前两处 WorkBuddy 目录、下面的同步片段也只遍历那两个 →
       照那段跑就会漏掉 trae-cn 那份，正好是本节要防的静默漂移。
     · **2026-09-24** 实测仍是 4 份，但**成员换了**：`.trae-cn` 已消失，多出 **`~/.zcode/`**
       （`~/.workbuddy-ai` / `~/.workbuddy` / `~/.zcode`）。
     · **2026-10-12** 实测 **6 份**，且**首次出现「配置根」类位置**：项目根 + `~/.workbuddy-ai/`
       + `~/.workbuddy/` + `~/.trae-cn/`（又回来了）+ **`<项目根>/.dsh/skills/`** + **`~/.dsh/skills/`**。
       前四份 `~/.*/skills` 能扫到，**后两份扫不到** —— 正是新增那条「配置根」提示要防的漏网。
     ⇒ 位置一律**现场发现**，并把「有哪些副本」当作**每次会话都要重算**的事实 ——
       不要引用本文档（或任何记忆）里的枚举，它们只说明「历史上出现过哪些」。
   - **项目根那份是权威源**（它进了仓库，可 review、可回溯），**先改它**。
   - 改完**按字节复制**，并核验 `diff` 为空 —— **遍历所有已存在的副本，不硬编码目录**：
     ```bash
     # SKILL 填本技能的目录名；遍历所有工具的 skills 目录，已有同名副本的逐个同步并核验
     SKILL=memory-handoff
     for d in ~/.*/skills; do
       [ -d "$d/$SKILL" ] || continue
       cp SKILL.md "$d/$SKILL/SKILL.md"
       diff -q SKILL.md "$d/$SKILL/SKILL.md" >/dev/null && echo "✅ $d/$SKILL/SKILL.md"
     done
     ```
     ⚠️ **上面这段只覆盖 `~/.*/skills` 一类** —— 项目级/配置根那类副本（见上，如 DSH 的
     `<项目根>/.dsh/skills/`）**不在遍历范围内，必须单独补**：
     ```bash
     # 配置根类副本：项目根那份是权威源，按字节复制过去并核验
     for d in .dsh/skills "$HOME/.dsh/skills" .agents/skills "$HOME/.agents/skills"; do
       [ -d "$d/$SKILL" ] || continue
       cp SKILL.md "$d/$SKILL/SKILL.md"
       diff -q SKILL.md "$d/$SKILL/SKILL.md" >/dev/null && echo "✅ $d/$SKILL/SKILL.md"
     done
     ```
     判据：**同步脚本要能覆盖「所有已知副本类型」，而不是只覆盖 home 点目录这一类** ——
     漏一类就是本节要防的静默漂移。**改完用「逐份 `diff`」收尾，而不是只信脚本跑过了。**
   - **会话开始时顺手核一次**（还是那条 `diff`）。漂移不会自己报警，
     只会在某次「照着旧规则办事」时才暴露。
   - ⚠️ **Windows 上先排除「纯行尾差」再谈漂移**：副本若是 CRLF、项目根是 LF，
     `diff` 会报**整篇**不一致（每一行都不同），看起来像大规模漂移，实际一个规则都没变。
     判据：**`diff --strip-trailing-cr 项目根/SKILL.md 副本`** 为空 ⇒ 只是行尾差，
     按「项目根是权威源」把它复制过去统一即可（2026-11-02 实测：4 份副本全是 CRLF，
     内容与项目根逐字一致，复制后 `diff` 才变空）。
     反过来，**逐字节不一致但 `--strip-trailing-cr` 也非空**才是真漂移。

### 续写与体量控制（实践补充）

**日志续写**：同一日期内多轮工作时，用 `## 续N：<主题>` 追加在**文件末尾**，
`N` 必须**递增**。序号重复或段落乱序会让下一个会话按序号读错顺序
（真实案例：`## 续十` 出现两次，且第二段物理位置排在 `## 续十二` 之后）。
若已写错，就地改名并在段首注明原因，不要靠"读的时候小心点"。

**MEMORY.md 要有体量预算**：它是**每次会话开头都要读**的文件，不是归档。
建议按 **~50 KB** 设上限（约 1.5 万 token）；超了就蒸馏，口径是
**「铁律 / 判据 / 决策一条不删，只删『我是怎么发现的』这类过程叙述」**。
⚠️ **预算是「触发蒸馏的信号」，不是「必须压到的目标」**：真到「只剩规则」时，
**再压就是删铁律**——那时应停下来如实登记「已达下限、超了多少、为什么不再压」，
或**把成块的细节继续下沉到 `topics/`**，而不要为了凑数字牺牲判据。
（沿革：2026-10-15 由 ~40 KB 上调为 ~50 KB，即为此原因 —— 历次蒸馏多次卡在
41~43 KB，再往下只能删规则。）

**蒸馏必须先归档、再重写**：把原文件整份复制到 `<项目根>/.memory/_archive/MEMORY-<日期>.md`
（一字不删），重写后在文件头写明「本文件是提炼层 + 归档路径」。
这样即使蒸馏漏了细节，也还能 grep 回来。

**蒸馏 / 复扫时逐条回磁盘核对**：记忆里「已修 / 未修」的字样**一律不可信**
（它是上一个会话当时的认知）。真实案例：一次蒸馏顺带纠正了 3 处过时记忆
——整节讲的系统已被移除、一个"未修"的缺口其实早修完了、以及一个"某目录是唯一生效位置"
的断言按当前工具已不成立。**凡是能从磁盘验证的结论，就去验证。**

### 无指令文件机制时的提示词模板

```
开始前，请先读取以下文件以了解此前的工作：
- <项目根>/.memory/MEMORY.md
- <项目根>/.memory/<YYYY-MM-DD>.md（最近的一两个日期，格式为四位年-两位月-两位日）

先读最新的日志，再至少往前看两天。
先总结当前进度、已定结论和待办事项，然后再开始干活。
```
