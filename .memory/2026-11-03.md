## 续18：P6 任务与投票完成（34 项验收全过）

### 已定结论

1. **任务是「转移」不是「生成」**：发布时 `score → frozen_score`（总资产不变，**不写 ±N 流水**），
   审核通过时 `frozen -N` → 完成者 `score +N`，写两条 ±N 流水，家庭总积分不变。
   ⇒ 冻结/解冻属于「同一成员内部额度调整」，只写一条 **0 分说明流水**（「发布任务：xxx（冻结 N 分）」），
   让流水看得出钱去哪了，又不污染得分榜（得分榜只算 `points > 0`）。
2. **投票口径**：分母 = 成员数 − 1（发布者）；通过 = `approve*2 > voters`；
   **提前驳回** = `approve + 剩余未投 ≤ voters/2`（剩余票全给同意也过不了）。
3. **超时用惰性清扫**：没有 cron，在 list/detail/vote 这些读路径上把过期提交置 `expired`。
   家庭量级足够，且不会因为漏跑定时任务而永远停在 `submitted`。
4. **重提上限**按 `rejected` 计数（`expired` 不计入），达 3 次锁定。

## 续22：Android 15 界面高保真原型（design/android-prototype.html）

### 做了什么

单个自包含 HTML（无外部依赖、无网络字体），按 375×812 绘制 15 个界面，
以 3 列网格铺成一张设计板；手机外壳 320×693（`transform: scale(.80533)` 等比缩放）。
点击任一屏幕可放大到 1:1（lightbox），Esc 关闭。

### 关键约定（画之前定的，避免返工）

1. **字段不自由发挥**：所有数值、状态、文案都对齐第 3 节表结构与已关闭的决策。
   - 积分榜显示「可用 + 冻结」，行内注明「其中 X 冻结中」（11.2.1）
   - 得分榜才有 周/月 切换，周一起算（11.2.2）
   - 头像只用 emoji 预设（🐻🦊🐰🐼），**全系统无上传入口**（19.14）
   - 任务卡显示「发布者 / 截止 / 状态」，自己发布的不出现在待接取
   - 投票卡带「已同意 X / 需 Y 票过半」「发布者无投票权」「剩余时间」
   - 屏幕时间页只有「自动上报」状态，**没有手动填写入口**（12 节）
2. **组长专属界面（13.13–13.15）在成员视角不出现**，不是置灰 —— 原型用紫色「仅组长」角标标注。
3. 主 Tab 五个：首页（榜）/ 任务 / 商城 / 通知 / 我的；13.13–13.15 从「我的 → 组长管理」进入。

### 画的过程中修掉的三个真问题

| 问题 | 后果 | 修法 |
|---|---|---|
| `.grow{flex:1}` 只写在 `.row .grow` 下 | 卡片里（非 `.row`）的右侧数值/按钮**不会右对齐**，挤在文字后面 | 改成全局 `.grow` |
| 邀请码卡片按钮宽度 auto | 邀请码与「复制」按钮几乎贴上，视觉拥挤 | 按钮固定 66px、邀请码 `letter-spacing` 4→3px |
| 柱状图容器 56px 装不下「柱 + 星期标签」 | 柱子溢出到标题行，和「阈值 120」重叠 | 容器 76px、柱高按比例下调 |

### 验证方式（本次新增，值得复用）

用 Edge headless 截图核对，而不是「凭感觉认为画对了」：

```bash
msedge --headless=new --disable-gpu --hide-scrollbars \
  --window-size=1500,2400 --screenshot=out.png file:///.../android-prototype.html
```

逐屏细看时用临时副本 + `figure:nth-of-type(n){display:block}` 只显示一屏，放大到 700×900。
**这个手段能发现纯读代码发现不了的排版问题**（上面三个 bug 全是这么抓到的）。
临时文件用完即删，不入库。
